环测 LIMS 当前流程与角色清单
============================

文档用途
--------
本文件记录当前 Main_V2 分支实际实现的订单流程、流程节点、状态枚举、角色职责和数据范围。
它是开发、测试、部署和员工培训的基准文档。若代码与本文档不一致，应先核对代码和更新日志，再修改本文档。

一、当前有效角色
----------------

1. 总经理
   - 原“董事长”角色的现用名称。
   - 全局订单、实验室、报告和财务查看；商务评审；员工账号管理；全局管理操作。
   - 保留原董事长的权限边界，角色重命名不改变流程权限。

2. 常务副总经理
   - 原“总经理”角色的现用名称。
   - 技术评审；订单执行路径和主责实验室分配；报告终审；经营总览和跨实验室查看。

3. 销售
   - 创建和维护本人负责的订单；提交订单；在允许节点发起修改或退单。
   - 对本人订单的检测报告执行销售初审。

4. 销售经理
   - 查看销售范围内的订单和销售总览，支持订单查询、导出和追溯。
   - 不替代总经理或常务副总经理执行双评审，不替代会计执行财务写入。

5. 商务部
   - 订单协同、下单、订单全局查询、路径/排期协调、报告初审和订单档案追溯。
   - 商务部可协助流程处理，但正式商务评审责任角色为“总经理”。

6. 苏州实验室
   - 苏州实验室负责人角色。
   - 只处理分配到苏州实验室的任务；可排期、确认样品、开展/结束实验、提交结果，并由本订单主责负责人汇总出具报告。
   - 订单金额和合同附件按当前隐私规则隐藏。

7. 江阴实验室
   - 江阴实验室负责人角色。
   - 只处理分配到江阴实验室的任务，职责与苏州实验室负责人相同，但数据范围限定为江阴实验室。
   - 订单金额和合同附件按当前隐私规则隐藏。

8. 实验操作员
   - 后端是统一角色名称，不拆成两个权限角色。
   - 通过员工实验室档案的 lab_type 绑定一个实验室：1=苏州，2=江阴。
   - 前端显示为“苏州实验室操作员”或“江阴实验室操作员”。
   - 只能操作所属实验室范围内的排期、样品、实验和结果；订单金额和合同附件隐藏。

9. 委外供应商
   - 处理委外执行路径的实验任务和结果回传。
   - 不能执行内部实验室任务、报告审核或财务操作。

10. 会计
    - 任意未退单、未办结阶段登记阶段开票和多次回款。
    - 终审通过后执行最终总开票；可作废发票、维护回款和校验余额。
    - 开票和回款写操作仅会计角色可执行。

11. 质量部（历史 V1 角色）
    - 仅兼容历史质量部调度流程、历史排期、样品和报告数据。
    - 当前 V2 技术直达实验室流程不再使用质量部作为主责调度角色。

角色兼容说明
--------------
“技术”和“商务”是历史代码/历史数据兼容名称，不属于当前新建账号的有效岗位选项。
当前正式岗位名称为“总经理”“常务副总经理”和“商务部”。

二、订单主流程
--------------

流程总览：

销售/商务部下单
  -> 总经理商务评审 + 常务副总经理技术评审（双评审，独立通过）
  -> 常务副总经理分配执行路径、主责实验室负责人
  -> 实验室排期
  -> 样品到达/入库
  -> 实验开始
  -> 实验结束并提交实验结果
  -> 主责实验室负责人汇总并出具报告
  -> 销售初审
  -> 常务副总经理终审
  -> 会计最终总开票
  -> 订单开票办结

节点说明：

1. 创建订单
   - 操作角色：销售、商务部；总经理保留全局管理能力。
   - 初始订单状态：待评审。
   - 创建时可上传合同，但合同仅创建销售、商务部和会计可见。

2. 双评审
   - 商务评审：总经理。
   - 技术评审：常务副总经理。
   - 两个评审独立记录，任一驳回会退回销售补充或修改；两项通过后进入排期。
   - 评审通过不是同一个按钮替代两个责任，必须分别完成对应评审。

3. 执行路径和负责人分配
   - 责任角色：常务副总经理；商务部可协同排期和路径协调。
   - 可配置苏州内部实验室、江阴内部实验室、外部委外或多路径并行。
   - 内部路径必须绑定对应实验室负责人；主责负责人负责最终汇总出具报告。

4. 排期
   - 责任角色：对应实验室负责人；商务部可协同处理排期。
   - 内部实验室只能选择同实验室设备，系统校验设备冲突和排期时间。
   - 排期变更会产生变更记录，并在必要时重新确认排期。

5. 样品到达、入库和出库
   - 责任角色：对应实验室负责人、所属实验室操作员；历史 V1 可由质量部处理。
   - 样品照片、样品登记和样品状态绑定具体实验路径。
   - 合同和报价金额不属于实验室操作范围。

6. 实验执行
   - 责任角色：对应实验室负责人、所属实验室操作员；委外路径由委外供应商执行并回传。
   - 实验操作包含开始实验、结束实验、填写原始数据/临时结论、提交实验结果。
   - 多路径订单需要所有执行路径完成并提交结果后，订单才进入出具报告节点。

7. 汇总并出具报告
   - 责任角色：订单主责实验室负责人；历史 V1 兼容质量部。
   - 选择正式版或草稿版，生成报告 PDF；当前模板化 PDF 链路可用，在线 Word 编辑、图片排版和 Word 导出属于后续升级范围。
   - 报告出具后进入待销售初审。

8. 销售初审
   - 责任角色：订单所属销售；商务部可按当前权限协助初审。
   - 初审通过进入常务副总经理终审；初审驳回退回报告重制。

9. 常务副总经理终审
   - 责任角色：常务副总经理。
   - 终审通过后报告状态为审核通过待开票；驳回退回报告重制。

10. 开票和回款
    - 责任角色：会计。
    - 订单未退单、未办结且未完成最终报告审核时，可阶段开票；开票金额累计不得超过订单报价。
    - 任意未退单、未办结阶段均可多次登记回款；回款金额累计不得超过订单报价，并记录回款时间和必填备注。
    - 最终总开票必须在报告终审通过后执行，并开完订单剩余可开票金额。
    - 发票支持作废、回款状态/明细和余额校验；所有流程完成后订单进入已开票办结。

三、订单状态枚举
----------------

LabOrder.Status：

1  PENDING_REVIEW   待评审
2  REVIEW_REJECTED  评审驳回
3  SCHEDULING       排期中
4  TESTING          试验中
5  REPORT_REVIEW    报告审核中
6  INVOICED_CLOSED  已开票办结
7  CANCELLED        退单
8  TEST_FINISHED    实验结果已提交待出报告
9  RESULT_PENDING   实验已结束待提交结果

执行路径状态：

SchedulePlan.Status：1 新建；2 变更待调整；3 执行中；4 实验已结束待提交结果；5 结果已提交。

实验记录状态：

Experiment.Status：1 待开展；2 试验中；3 实验已结束待提交结果；4 结果已提交。

报告状态：

TestReport.Status：1 草稿；2 待销售初审；3 待常务副总经理终审；4 审核驳回重制；5 审核通过待开票。

四、重要权限边界
----------------

- 总经理和常务副总经理是两个不同角色，前者负责商务评审/全局管理，后者负责技术评审/报告终审。
- 苏州实验室和江阴实验室负责人是两个独立角色，不能用一个 lab_type 同时表达两个负责人范围。
- 实验操作员是统一权限角色，但每个操作员档案当前只能绑定一个实验室。
- 实验室负责人和实验操作员不能查看订单报价金额，也不能查看合同附件。
- 合同附件仅创建销售、商务部和会计可见。
- 会计是开票和回款的唯一写入角色；其他角色只能按权限查看相关财务信息。
- 订单状态推进由后端流程动作校验，前端按钮只是可操作入口，不能替代后端权限校验。

五、流程分支
------------

- 评审驳回：返回销售/商务补充信息，重新进入双评审。
- 订单变更：样品到货前或实验过程中可发起，需重新调整相关排期并留存变更记录。
- 外部委外：由委外供应商执行并回传结果，主责实验室负责人汇总后继续报告流程。
- 多路径并行：苏州、江阴、委外可以并行，所有路径提交结果后才允许出具总报告。
- 报告初审驳回或终审驳回：进入报告重制，再重新提交审核。
- 阶段开票/多次回款：不推进主流程，不代表订单办结；最终办结仍受报告终审和最终总开票约束。
- 退单：退单后禁止继续实验、报告和财务写入操作。
