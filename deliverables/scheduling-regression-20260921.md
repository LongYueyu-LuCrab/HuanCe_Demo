## 排查结论

| 角度 | 问题与证据 | 修复 |
| --- | --- | --- |
| 前端入口 | 实验室工作台的 V2 待排订单显示“无可操作”；工作台未向通用订单表传入用户，原操作计算也没有负责人排期入口。 | 从会话读取实验室角色，明确展示“排期 / 查看任务”，进入订单详情中的当前实验室操作。 |
| 前端表单 | 大段订单详情位于排期输入框之前，关键日期、设备及提交操作不够显眼。缺少直观的空日期、未选设备反馈。 | 排期表单前置，详情折叠；增加日期完整性、日期先后、内部任务必选设备校验。 |
| 后端待办 | 新待排任务会被历史 V1 变更任务挤到后面。 | V2 尚未排期的有效任务优先展示，保留角色范围过滤。 |
| 前后端衔接 | 订单详情中的待变更任务仍发送普通排期动作，与后端变更保护冲突；深链接只从已加载列表查找任务，列表范围之外无法打开，重复打开也受旧参数影响。 | 待变更任务进入“处理变更并排期”；按订单详情解析指定任务，打开后消费动作参数。 |
| 设备查询交互 | 更改日期或任务后，旧设备查询响应可能回写；查询反馈不充分。 | 过期响应丢弃，切换日期/任务清空旧选择，展示可用数量及设备不可用原因。 |
| 流程一致性 | 已经销售确认的订单改动排期日期或设备后，旧确认仍有效。 | 实质改期撤销销售确认，回到待确认；相同日期和设备重复保存保留确认；失败操作整体回滚。 |
